# Knowledge

这里是 `To-be-a-better-PM` 的 Markdown 知识源目录。

## 定位

- `knowledge/` 放待 review 的原始 Markdown 知识笔记。
- `docs/` 放已经整理为 GitHub Pages 的静态 HTML/CSS/JS 发布资产。

## 工作流

1. 先把一次有价值的讨论、阅读、复盘或问题链整理成 Markdown，放入 `knowledge/`。
2. Markdown 要保留原始问题、推理过程、关键判断、反例、未解决问题和需要事实核验的部分。
3. Review 通过后，再把一篇或多篇 Markdown 聚合、改写或设计成 HTML 页面，放入 `docs/` 并更新站点导航。

## 命名建议

使用日期加主题的 kebab-case 文件名：

```text
YYYY-MM-DD-topic-summary.md
```

例如：

```text
2026-06-16-china-economic-transition-old-cycle-new-cycle.md
```
